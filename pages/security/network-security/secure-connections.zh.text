@title = '安全连接'

h2. 什么是安全连接？

使用 Riseup 的服务时，你应该启用加密。如果不使用安全连接，你的互联网流量就没有加密。这意味着任何想窃听你邮件的人都能监听你的通信；更糟的是，他们可以轻易拿到你的登录名和密码，或者冒充我们的服务器。与 Riseup 建立安全连接，可以为你提供合理的保护，防范窃听者和冒充者。

h2. 如何使用安全连接？

要让邮件客户端使用安全连接，你需要修改一些配置。别担心！我们会一步步带你完成。

如果你确定自己用的是 Thunderbird，可以直接跳到下面的[[Thunderbird 部分 => /secure-connections#thunderbird]]检查设置。如果你用的是其他邮件客户端，请阅读[[通用设置部分 => /secure-connections#general-settings]]。如果你完全不知道邮件客户端是什么，请读下一节，我们会解释。

h2. 什么是邮件客户端？

邮件客户端是专门用来收发和撰写电子邮件的程序。它可能是 Thunderbird、Apple Mail、Outlook、Eudora 等等。你用来读写邮件的那个程序，就是你的邮件客户端。

h2. 通用设置

一般来说，你需要打开邮件程序的配置设置，确保所有连接都使用 SSL 或 TLS（也就是 POP 或 IMAP 连接，以及 SMTP 连接），并确认端口号正确。如果你不明白这些术语，别担心，我们会带你操作。

具体步骤在不同邮件客户端之间差别很大，有时同一软件的不同版本也会很不一样。

一般来说，我们不提供邮件客户端的技术支持。不过，我们有一些关于[[配置邮件客户端的通用信息 => email/clients]]。如果你的客户端在列表里，那里的信息能帮你完成所需的修改。

如果你用的不是 Mozilla 的 Thunderbird，我们想花一点时间建议你考虑换过来。它是一个相当安全、易用、自由的软件项目，试一试不会有坏处！[[最好的一点是，我们的 Thunderbird 设置指南 => thunderbird]]写得很好，这是我们最熟悉的客户端，如果你用它，我们也更容易提供支持。

如果你不想换到 Thunderbird，又不熟悉如何自己修改设置，而且我们的帮助页面也帮不上忙，你就需要向身边懂技术的朋友，或者软件供应商/社区寻求帮助，了解如何完成所需的配置修改。

h2. Thunderbird

要在 Thunderbird 中完成所需的修改，请按以下步骤操作：

首先，点击“帮助”菜单 --> “关于 Thunderbird”，查看你的 Thunderbird 版本。

确定版本号后，按你的版本选择下面的流程。如果你用的是 Thunderbird 2.x 或更老的版本，你真的需要升级了！很遗憾，我们无法在这里介绍如何升级，但你可以在网上搜索“upgrading thunderbird”，找到大量信息。

h3. Thunderbird 3.x 及更新版本

要在 Thunderbird 3.x 中启用安全连接，请按以下步骤操作：

* 从“编辑”菜单中选择“账户设置”，
* 账户设置对话框弹出后，选择你 Riseup 账户的“服务器设置”
* 在对话框中间，你会看到一个标题“安全设置”
* 标题下面有一个下拉菜单，标着“连接安全”
* 这个下拉菜单应该设置为 SSL/TLS
* 在对话框右上角，有一个“端口”设置
* 它通常会自动填好，但还是检查一下
** 如果你使用 IMAP，端口号应该是 993
** 如果你使用 POP，端口号应该是 995
* “服务器设置”对话框顶部有一行“服务器类型”，告诉你当前用的是 IMAP 还是 POP
* 接下来，点击左侧窗格中的“发送服务器（SMTP）”
* 在右侧窗格中单击 Riseup 的 SMTP 服务器
* 点击对话框最右侧的“编辑”
* 把“连接安全”设置为 SSL/TLS
* 确认“端口”设置为 465
* 点击“确定”
* 再点击一次“确定”
* 任何时候都不要修改“身份验证方式”设置——它应该始终是“普通密码”
* 大功告成！！！太好了！

h2. 常见问题

问：如果我使用网页邮箱，它是安全的吗？

答：使用网页时，你的电脑会经过互联网上的各种服务器，连接到你访问的网站的网页服务器。这个连接使用的是“HTTP”，以明文传输，并不安全。攻击者可以借此进入你的网站账户，获取你在浏览网页时发送或接收的任何信息。不过还有希望！“HTTP”有一个安全版本，叫“HTTPS”（注意多出来的那个表示安全的“s”）。HTTPS 旨在提供能抵御攻击的安全连接。

为了进一步保护安全，你应该考虑核实自己访问的网站确实是想要访问的那个。使用 HTTPS 时，你会从服务器收到一份证书，证书的作用就是证明这是正确的服务器。要核实网站是不是你想访问的那个，你应该[[验证服务器出示的证书是否正确 => /certificates]]。

关于证书，还有一些问题你需要了解（见下文“安全连接的局限性”）。

看看地址栏里的 URL。如果它以 <code>https://</code> 开头（注意那个“s”），你就在使用安全连接；如果只是 <code>http://</code>（没有“s”），那就不是安全连接。你可以在地址栏里把“http”改成“https”，补上那个“s”，然后按“Enter”键，以安全方式加载页面。

第三种、也远不如前两种可靠的方法，是找一个小锁图标。它可能出现在地址栏里，也可能在窗口角落（位置取决于你用的浏览器）。锁应该是闭合的；如果没有锁，或者锁看起来是打开的，你就没有使用安全连接。你可以把鼠标悬停在锁上查看详细信息；通常点击（有时是右键点击）这个锁，会显示用于保护该连接的 SSL 证书详情。

问：POP/IMAP 和 SMTP 是什么？

答：POP 和 IMAP 是软件从远程邮件服务器收取邮件时常用的协议。通常你会用其中一个，而不是同时用两个。SMTP 是另一种常见的邮件传输协议，用来把你的邮件从电脑发送到邮件服务器。

问：如果我自己配置邮件软件，应该用哪些端口号？

答：使用 TLS 的 POP 连接，端口号是 995。
   使用 TLS 的 IMAP 连接，端口号是 993。
   使用 TLS 的 SMTP 连接，端口号是 465。

问：如果我对安全使用互联网电子邮件还有更多问题怎么办？

答：如果你仔细阅读了 [[Riseup 帮助页面 => https://help.riseup.net]] 之后仍有问题，我们鼓励你提交一份 [[Riseup 帮助工单 => https://support.riseup.net/]]。我们很乐意帮助用户了解如何让通信更安全，也乐意为提升所有互联网用户的隐私出一份力。

h2. 安全连接的局限性

现在你已经在使用安全连接了，一切都完全安全了，对吧？很遗憾，并不是！安全连接只保护数据在传输过程中的安全，并不保证特定数据的保密性。例如，使用安全连接发送邮件时，邮件在发往我们的邮件服务器和从我们的服务器发出的过程中是加密的；但从我们的服务器到最终收件人的途中，邮件还要经过互联网上的许多“跳”。这些跳转很少加密，所以别人有很多机会获取你的邮件——无论是在互联网上“传输中”，还是在某台邮件服务器上“静止”时，或者在最终收件人的电脑上。切换到安全连接，真正能保证的只是：你登录我们服务器时，用户名和密码是安全的。

那么，还能做什么来更好地保护电子邮件通信？如果你想要完整的端到端安全，就需要[[使用 OpenPGP 这类强加密软件 => openpgp]]，并让你通信的对象也开始使用它。有一个叫 [[Enigmail 的 Thunderbird 插件 => enigmail]]，可以很方便地把强加密集成到 Thunderbird 中。

网上的安全围绕 HTTPS 展开，而这又涉及判断某个服务器的证书是否应被浏览器视为“有效”。目前的做法是：浏览器会分发一份“受信任”的证书颁发机构列表。这很糟糕，因为它要求你作为用户，把验证安全连接的权力交给某种中央权威；你为什么会愿意为了进行安全通信，而听命于这些自封的权威呢？想了解更多关于这种做法为什么糟糕，可以读读这篇关于[[技术架构如何塑造我们的社会结构 => http://lair.fifthhorseman.net/~dkg/tls-centralization/]]的文章，以及这种集中化的控制等级为什么极其有问题。
