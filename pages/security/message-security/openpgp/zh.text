h2. 什么是加密电子邮件？

加密电子邮件是一种保护邮件内容、防止它在互联网上传输时被窃听的方法。最常见的加密类型是 OpenPGP（OpenPGP 是规范；PGP 是“Pretty Good Privacy”，属于专有软件；GPG 是 GNU Privacy Guard，属于自由软件）。互联网上有很多资源可以详细解释加密原理。对我们来说，理解三个组成部分就够了：*公钥*、*私钥*和*密码短语*。

顾名思义，你的*公钥*是公开可得的。有时人们会用密钥服务器共享公钥，让加密邮件的发送更方便。每当你想发送加密邮件时，都必须拿到收件人的公钥。同样，别人想给你发送加密邮件时，也必须拿到你的公钥。

一把*私钥*只与一把公钥对应。没有私钥，要提取加密消息的内容极其困难。在超级计算机时代，没有什么是不可能的，但没有私钥解密消息仍然异常困难。你的私钥极其重要，任何时候都应该放在安全的地方。

你的*密码短语*长度至少应为 21 个字符，并包含大写字母、小写字母以及符号（&$"{@）。密码短语用于解锁私钥，让它与公钥配合，收发加密邮件。

h2. 我如何使用加密电子邮件？

使用 GPG 可以完成三种基本操作：*签名*、*加密*和*验证*。

*签名*：签名时，你用自己的私钥和密码短语生成一个*签名块*，附加在你签署的内容后面。这个签名块由两样东西生成：（1）根据消息内容计算出的数值；（2）你的私钥。

*验证*：当有人收到已签名的内容时，可以用对应的公钥来验证。公钥可以从密钥服务器下载，也可能由发件人通过邮件发来。验证可以确认两件事：第一，消息是由某个能访问对应私钥的人签名的；第二，消息内容在传输过程中没有被修改。

*加密*：要加密一条消息，你需要收件人的公钥。你不需要密码短语，甚至不需要自己的 GPG 密钥，就能加密内容。不过，大多数程序在发送时也会用你自己的公钥加密一份；否则消息一旦加密，你自己也读不了了。消息加密后，内容在传输过程中就无法查看。*但是，主题、发件人和收件人仍然可见。*

h2. 我能用 Riseup 的网页邮箱收发加密邮件吗？

目前还不行。对想使用加密邮件的 Riseup 用户来说，更好的做法是使用[[邮件客户端 => email/clients]]（例如 [[Thunderbird => email/clients/thunderbird]]）收发邮件，并把私钥安全地保存在本地电脑上。

h2. 加密通信有哪些局限？

加密通信无法保护你免受*关系监控*——也就是对人与人之间联系方式的监控。例如，如果 ihatebush@riseup.net 经常给 joehill@riseup.net 发送加密邮件，拦截通信的人可能不知道这两个人在聊*什么*，但“这两个人经常通信”这个基本事实本身就有价值。此外，邮件的主题行*没有加密*。

签名和验证并不能保证邮件确实是由与密钥关联的邮箱地址发出的。伪造回信地址非常容易。因此，一个拥有 federalagent@yahoo.com 邮箱的人可以：（1）为 joehill@riseup.net 创建一把密钥；（2）把这把密钥上传到公共密钥服务器；（3）从 federalagent@yahoo.com 发送一封看起来来自 joehill@riseup.net、并且带有签名的邮件。如果你只是下载公钥并验证消息，它会显示“来自 joehill@riseup.net 的良好签名”，可这封邮件根本不是 joehill 发的！这就是*信任网络*如此重要的原因（见下文）。

h2. 我如何验证密钥所有者的身份？

现在你已经配置好加密邮件，正开心地收发消息。但你怎么知道，自己真的在和以为的那个人通信？这就需要用到*密钥指纹*。

每一把公钥都有一个唯一的*指纹*。指纹通过哈希函数生成，哈希函数就像一个单向传送门：对于任何特定输入，都有*且只有一个*对应的输出。就像你的指纹是唯一的一样，任何一把公钥也只有一个指纹。这有什么用？因为要确认整个过程完整可信，你必须确保：当你收到一封来自 joehill@riseup.net 的签名邮件时，它确实来自你的朋友 Joe Hill。有三种（也可能是两种）方法可以做到这一点：

   1. 你和 Joe 当面见面，Joe 把公钥的电子副本交给你。
   2. 你和 Joe 当面见面，Joe 把密钥指纹的副本交给你，你核对指纹与公钥的指纹是否一致。
   3. （安全性较低）如果你非常了解 Joe，能认出他的声音，Joe 可以在电话里把指纹读给你听。

指纹不是秘密信息——任何人都可以用公钥生成指纹。

h2. 我如何给密钥签名，为什么要这样做？

再进一步。假设你已经以安全的方式和 Joe 交换了密钥。现在你可以放心地给 Joe 发加密邮件，因为你知道自己确实在和他通信（他会给邮件签名），也知道通信内容不会被窥探（你在用 Joe 的公钥加密邮件）。但假设 Joe 在一次行动中认识了 Rita，Joe 和 Rita 也以安全的方式交换了密钥。你认识并信任 Joe，但没见过 Rita。你怎样才能在不亲自见她的情况下，确认 Rita 的密钥是真的？

这就轮到信任网络和密钥签名了。

一旦 Joe 以安全方式验证了 Rita 的密钥，Joe 就可以*给 Rita 的公钥签名*。关于密钥签名，有两种观点。一种认为，只有当你核实了与邮箱地址关联的真实姓名，确实与*政府签发*的带照片身份证件（例如护照）一致时，才应该给别人的密钥签名——即使对方是你认识很久的人。另一种则不给真实姓名做验证，只确认“这个邮箱地址的主人就是这把密钥的主人”，但不确认“与这个邮箱地址关联的真实姓名就是这把密钥的主人”。

如果你信任 Joe 会认真验证每个人的密钥，就可以在自己的密钥环里为 Joe 的密钥设置一个信任级别。这样，即使你没有亲自见过某人来验证其密钥，但 Joe 见过，你就可以因为 Joe 给那把密钥签了名，而给它设定一个信任级别。

你可以举办*密钥签名聚会*，鼓励朋友和同事交换密钥并互相签名。这样，即使某些人你没见过，但你信任的人见过他们，你也有办法验证他们的身份。

h2. 关于加密电子邮件，还有其他建议吗？

很高兴你问了！

* *一定要*把私钥保存在加密的硬盘分区上——这样即使电脑丢失、被盗或被扣押，也能保护密钥的完整性。
* *不要*把私钥分享给任何人，也不要把私钥保存在公共电脑上。
* *使用强密码短语*——密码短语是你防止密钥被滥用的最后一道防线。不要因为用了弱密码短语而毁掉整件事。密码短语应长于 21 个字符，且不应包含词典里的单词或其他容易猜到的组合。*把随机生成的密码短语写下来、放在安全的地方，也比使用包含词典单词的长短语更安全。*
* *使用笼统的主题行*——邮件主题行不加密。因此，在加密通信中应始终使用非常笼统的主题行。
* *举办签名聚会*——鼓励朋友获取 GPG 密钥，并互相签名。
* *即使内容不重要，也发送加密邮件*——这一点至关重要！！如果只有秘密通信才使用加密邮件，可供分析的加密流量就会少得多。如果每个人都把所有通信都用加密邮件发送，哪怕只是讨论吃什么披萨，加密邮件的流量也会增加。
